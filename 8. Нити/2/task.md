# Плюсов мало не бывает

Проанализируйте следующий фрагмент C и перечислите все возможные выводы, если такая постановка корректна. Заголовки `<pthread.h>` и `<stdio.h>` опущены.

```c
void func(void* arg) {
    printf("%d\n", *(int*)arg);
    pthread_exit(NULL);
}

int main(void) {
    pthread_t t1, t2, t3;
    int a = 1;
    pthread_create(&t1, NULL, func, &a);
    pthread_create(&t2, NULL, func, &(++(a++)));
    pthread_create(&t3, NULL, func, &a);
    pthread_join(t1, NULL);
    pthread_join(t2, NULL);
    pthread_join(t3, NULL);
    return 0;
}
```

В исходном условии заявлены атомарность операций, отсутствие буферизации и успешность системных вызовов. Требуется проверить, позволяют ли эти гарантии вообще выполнить записанную программу. Выражение `&(++(a++))` приведено намеренно без исправления: нельзя подменять его другим выражением и анализировать уже другую программу.

Источник: «Задачи.md», раздел «Задачи на нити», «Плюсов мало не бывает».

---

# решение

**Программа некорректна на этапе трансляции C; определённого множества выводов нет.**

Постфиксное выражение `a++` возвращает значение до увеличения, а не модифицируемое lvalue. Префиксный `++` требует модифицируемое lvalue, поэтому `++(a++)` нарушает ограничение языка. Дополнительно результат префиксного `++` в C сам не является lvalue, к которому можно применить обычный оператор взятия адреса `&`.

Нельзя трактовать выражение как «дважды увеличить `a` и передать адрес `a`»: это не семантика C. Ни успешность системных вызовов, ни атомарность не исправляют недопустимый операнд языкового оператора.

Есть и независимая ошибка: функция нити имеет тип `void (*)(void *)`, тогда как `pthread_create` ожидает `void *(*)(void *)`. Исправление только выражения не сделало бы весь фрагмент корректным.

Если заменить выражение на допустимую последовательность изменений `a`, также потребуется синхронизация: первая нить может читать `a` одновременно с изменениями в `main`. Отсутствие буферизации `printf` не устраняет такую гонку. Конкретное исправление и порядок изменений не заданы, поэтому единственного «задуманного» списка чисел восстановить нельзя.

# МАБФ: структурная ёмкость, вариант 4

В файловой системе размер блока `N = 40` байт, размер записи с номером блока `s = 1` байт, длина массива адресов блоков файла (МАБФ) `L = 17` записей. Найдите максимальное число блоков **данных** одного файла, допускаемое структурой адресации.

Восстановленное соглашение: используется классическая Unix-схема — `L − 3` прямых адресов и по одному адресу блока однократной, двукратной и трёхкратной косвенности. Каждый косвенный блок содержит `q = N / s` записей. Сам МАБФ находится вне учитываемых блоков данных; косвенные блоки содержат адреса, а не данные файла.

Отдельно обсудите, достижим ли структурный предел при конечном диапазоне номеров блоков. В исходнике не задано кодирование номеров и не сказано, зарезервирован ли ноль. Для численного сравнения дополнительно рассмотрите обычное соглашение: запись — беззнаковое целое из `8s` бит, `0` означает отсутствие блока, номера всех блоков данных и косвенности лежат в одном диапазоне `1..2^(8s) − 1`. Доступных физических блоков должно быть достаточно; фактический размер ФС не задан.

Источник: «Задачи.md», «Быстросчет блоков», вариант 4.

---

# решение

В одном косвенном блоке `q = 40 / 1 = 40` записей; прямых адресов `d = 17 − 3 = 14`.

Структурная ёмкость данных:

`D = d + q + q² + q³ = 14 + 40 + 1600 + 64000 = 65654` блоков.

Это число блоков данных, а не сумма данных и таблиц. При полном заполнении структуры таблицы занимали бы `1 + (1 + q) + (1 + q + q²) = 1683` блоков; вместе с данными получилось бы `67337` блоков. Эти последние числа также описывают структурное дерево, а не гарантируют его физическую реализуемость.

Однобайтовая запись при принятом дополнительном соглашении позволяет адресовать только `255` различных блоков, включая таблицы. Поэтому число `65654` — структурный предел, а не реальное число различных блоков данных в такой ФС.

Точный максимум данных здесь — **248**. Можно разместить 14 прямых блоков, 40 блоков через однократную косвенность и 194 блока через двукратную. Таблиц требуется `1 + 1 + ceil(194 / 40) = 7`: одна однократно-косвенная, корень двукратной и пять её дочерних таблиц. Всего `248 + 7 = 255` блоков.

Для 249 блоков данных после прямых 14 нужно хотя бы `ceil((249 − 14) / 40) = 6` нижних таблиц. Только одна доступна непосредственно из МАБФ, следовательно, нужен ещё хотя бы один вышестоящий блок: суммарно не меньше `249 + 6 + 1 = 256` блоков. Это превышает диапазон. Трёхкратная косвенность не устраняет необходимость вышестоящих таблиц.

Исходник не резервирует ноль явно. Если все 256 байтовых значений допустимы как номера и отсутствие блока задаётся отдельно, доступно 256 номеров и аналогично достижимы 249 блоков данных с семью таблицами. Поэтому без соглашения о кодировании единственный физический максимум из исходных данных не следует; размер ФС тоже может дополнительно ограничить файл.

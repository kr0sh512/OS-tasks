# Найди меня: попроще

Источник: `Задачи.md`, «Найди меня», вариант «Попроще».

Дана допустимая иерархия PID:

```text
A
└── B
    ├── C
    │   └── E
    └── D
```

Программа запускается из неуказанного процесса. Не все нарисованные процессы обязательно создаются: но каждый созданный ребёнок должен соответствовать ребру этой иерархии. Порядок создания C и D в этом источнике отдельно не задан. Определите все совместимые начальные процессы, все способы назначения PID создаваемым процессам и все возможные выводы.

Рассматривается полный запуск `main`, без чужих детей и без ранее выполненной части этой программы; необязательные вершины не добавляют невидимые вызовы `wait`. Если рассматриваются несколько независимых полных запусков, один PID не может одновременно принадлежать двум экземплярам. Внешний родитель начального процесса не обязан ждать. Для начального A его неуказанный родитель обозначается Q. Это дополнительное обозначение необходимо, поскольку исходная схема не задаёт PID родителя A. Стандартное завершение `wait` с −1/ECHILD при отсутствии детей не считается запрещённой ошибкой: буквальная гарантия успешности всех `wait` противоречила бы коду. Иных ошибок нет.

Считайте каждый вызов `printf` атомарным и небуферизованным: одна строка не перемешивается с другой. Аргументы вычисляются до печати; между чтением PID родителя и самой печатью процесс может быть вытеснен. Все `fork` успешны. PID обозначены символами, а не конкретными числами. `R` — PID фактического усыновителя осиротевшего процесса (не обязательно 1); после усыновления он остаётся жив. Чужие процессы не создают и не завершают детей рассматриваемых процессов. Заголовки стандартных библиотек подразумеваются.

```c
int main(void) {
    if (fork()) {
        printf("%d %d\n", getpid(), getppid());
    } else {
        if (!fork()) {
            printf("%d %d\n", getpid(), getppid());
        }
    }
    wait(NULL);
}
```

---
# решение

Программа создаёт цепочку из трёх процессов: начальный S, ребёнок T, внук U. Все совместимые назначения:

```text
S   T   U   Внешний родитель S
A   B   C   Q
A   B   D   Q
B   C   E   A
```

Других стартов нет: начальный процесс должен иметь ребёнка, который способен создать собственного ребёнка. В частности, C не подходит: его ребёнок E не имеет допустимого ребёнка. Для старта A обе ветви B→C и B→D разрешены, поскольку отсутствующее C не обязано создаваться, а порядок детей в данном источнике не оговорён. Дополнительное соглашение «создаваемые дети обязаны заполнять список слева направо без пропусков» исключило бы вторую строку, но в исходной формулировке его нет. Независимые полные экземпляры не могут одновременно занять непересекающиеся допустимые трёхвершинные цепочки этой схемы.

Для каждой строки таблицы возможны ровно следующие четыре символических вывода, где H — указанный внешний родитель (Q либо A):

```text
S H
U T
```
```text
U T
S H
```
```text
S R
U T
```
```text
U T
S R
```

Всего 12 символических выводов для всех совместимых назначений. Q — реально существующий, но неизвестный из условия PID; без его задания нельзя перечислить единственное конкретное числовое множество. Если внешний родитель гарантированно жив до чтения, для соответствующего старта остаются только первые два вывода.

S печатает до своего `wait`, T вообще не печатает и ждёт U, U печатает и получает −1/ECHILD при своём ожидании. S ждёт T, поэтому U всегда видит T; порядок строк S и U свободен. Однако внешний родитель S в программе не контролируется, и S может увидеть усыновителя R. Успешность создания процессов не отменяет ECHILD у U.

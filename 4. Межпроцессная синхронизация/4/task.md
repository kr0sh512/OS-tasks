# Очередь сообщений: IPC_PRIVATE, права и MSG_EXCEPT

Источник: `Test_20251109.md`, задание № 7, вариант B.

Что будет выведено на экран? Если возможны несколько вариантов, приведите все. По исходному условию вывод атомарен и не буферизуется, все системные вызовы успешны, заголовочные файлы опущены, а `msgId` — идентификатор существующей пустой очереди сообщений.

```c
int main() {
    struct { long type; char data[1]; } msg;
    msgId = msgget(IPC_PRIVATE, 0);

    msg.type = 3; msg.data[0] = 'H'; msgsnd(msgId, &msg, 1, 0);
    msg.type = 1; msg.data[0] = 'e'; msgsnd(msgId, &msg, 1, 0);
    msg.type = 5; msg.data[0] = 'l'; msgsnd(msgId, &msg, 1, IPC_NOWAIT);
    msg.type = 7; msg.data[0] = 'l'; msgsnd(msgId, &msg, 1, 0);
    msg.type = 4; msg.data[0] = 'o'; msgsnd(msgId, &msg, 1, 0);
    msg.type = 8; msg.data[0] = 'D'; msgsnd(msgId, &msg, 1, IPC_NOWAIT);
    msg.type = 2; msg.data[0] = 'u'; msgsnd(msgId, &msg, 1, 0);
    msg.type = 1; msg.data[0] = 'd'; msgsnd(msgId, &msg, 1, IPC_NOWAIT);
    msg.type = 4; msg.data[0] = 'e'; msgsnd(msgId, &msg, 1, IPC_NOWAIT);

    msgrcv(msgId, &msg, 1, -2, 0); putchar(msg.data[0]);
    msgrcv(msgId, &msg, 1, 0, IPC_NOWAIT); putchar(msg.data[0]);
    msgrcv(msgId, &msg, 1, 1, MSG_EXCEPT); putchar(msg.data[0]);
    msgrcv(msgId, &msg, 1, -5, 0); putchar(msg.data[0]);
    msgrcv(msgId, &msg, 1, 4, IPC_NOWAIT); putchar(msg.data[0]);
    msgrcv(msgId, &msg, 1, 7, MSG_EXCEPT); putchar(msg.data[0]);

    return 0;
}
```

В листинге нет объявления `msgId`: для анализа исполнения явно предполагается внешнее объявление `int msgId;`. Без него это не самостоятельная корректная программа C, и одними заголовочными файлами отсутствие объявления не исправляется. Используется Linux System V IPC с доступным расширением `MSG_EXCEPT`.

Сначала проверьте права и согласованность условия; затем отдельно найдите вывод в модели, где очередь действительно доступна и все отправки успешны. Посторонних участников нет.

---
# решение

## Что происходит с очередью в записанной программе

`msgget(IPC_PRIVATE, 0)` создаёт **новую** очередь с режимом доступа `000`, а не открывает существующую. `IPC_PRIVATE` означает создание нового объекта, не предоставление владельцу исключительного права доступа. Упомянутая в общей преамбуле уже существующая очередь не используется: её идентификатор перезаписывается. Поэтому описание используемой очереди в преамбуле и листинге расходится.

Для обычного непривилегированного процесса режим `000` запрещает и отправку, и получение даже владельцу. Уже первый `msgsnd` завершается с `-1`, `errno == EACCES`. Предпосылка успешности всех вызовов тогда невыполнима. Ошибки кодом не проверяются; выдавать результат успешных операций за безусловный результат исходника нельзя.

На Linux процесс с действующей в соответствующем пространстве имён возможностью `CAP_IPC_OWNER` может обойти проверку прав. Поэтому утверждение «режим 000 абсолютно всегда запрещает операции любому процессу» тоже неверно. Без уточнения привилегий реальная постановка неоднозначна. Кроме прав требуется достаточная ёмкость: девять однобайтовых сообщений отправляются до первого получения. При условии успеха `IPC_NOWAIT` не создаёт дополнительных ошибочных вариантов, но само по себе его наличие успеха не обеспечивает.

Если отдельно отказаться от обещания успеха и рассмотреть обычный процесс без обхода прав, при успешном создании очереди все девять отправок и шесть получений завершаются `EACCES`. Структура остаётся после последней отправки с `data[0] == 'e'`; шесть безусловных `putchar` печатают `eeeeee`. Это поведение **вне** заявленной модели успешных вызовов, а не альтернативный успешный результат.

## Операционный ответ при явном исправлении предпосылок

Дополнительная модель: объявление `msgId` предоставлено; либо режим при создании явно изменён с `0` на `0600`, либо процесс имеет описанное право обхода; очередь вмещает не менее девяти таких сообщений; все вызовы успешны. Изменение режима — оговорённая модификация, а не исходный код.

Тогда единственный вывод — `eHldoD`, без перевода строки.

Исходная очередь после отправок:

```text
(3,H), (1,e), (5,l), (7,l), (4,o), (8,D), (2,u), (1,d), (4,e)
```

| Получение | Правило выбора | Данные |
|---|---|---|
| `-2, 0` | Минимальный тип ≤ 2 равен 1; первое сообщение этого типа | `e` |
| `0, IPC_NOWAIT` | Самое старое оставшееся сообщение любого типа | `H` |
| `1, MSG_EXCEPT` | Первое сообщение типа, отличного от 1 | `l` типа 5 |
| `-5, 0` | Минимальный оставшийся тип ≤ 5 равен 1 | `d` |
| `4, IPC_NOWAIT` | Первое сообщение точно типа 4 | `o` |
| `7, MSG_EXCEPT` | Первое оставшееся сообщение не типа 7 | `D` типа 8 |

`MSG_EXCEPT` изменяет выбор только при **положительном** `msgtyp`: это исключение указанного типа, не поиск минимального типа. После шести получений остаются `(7,l), (2,u), (4,e)` в указанном порядке. В частности, последний выбор пропускает старейшее `(7,l)` и берёт `(8,D)`.

# МАБФ: структурная ёмкость, вариант 2

В файловой системе размер блока `N = 512` байт, размер записи с номером блока `s = 2` байт, длина массива адресов блоков файла (МАБФ) `L = 15` записей. Найдите максимальное число блоков **данных** одного файла, допускаемое структурой адресации.

Восстановленное соглашение: используется классическая Unix-схема — `L − 3` прямых адресов и по одному адресу блока однократной, двукратной и трёхкратной косвенности. Каждый косвенный блок содержит `q = N / s` записей. Сам МАБФ находится вне учитываемых блоков данных; косвенные блоки содержат адреса, а не данные файла.

Отдельно обсудите, достижим ли структурный предел при конечном диапазоне номеров блоков. В исходнике не задано кодирование номеров и не сказано, зарезервирован ли ноль. Для численного сравнения дополнительно рассмотрите обычное соглашение: запись — беззнаковое целое из `8s` бит, `0` означает отсутствие блока, номера всех блоков данных и косвенности лежат в одном диапазоне `1..2^(8s) − 1`. Доступных физических блоков должно быть достаточно; фактический размер ФС не задан.

Источник: «Задачи.md», «Быстросчет блоков», вариант 2.

---

# решение

В одном косвенном блоке `q = 512 / 2 = 256` записей; прямых адресов `d = 15 − 3 = 12`.

Структурная ёмкость данных:

`D = d + q + q² + q³ = 12 + 256 + 65536 + 16777216 = 16843020` блоков.

Это число блоков данных, а не сумма данных и таблиц. При полном заполнении структуры таблицы занимали бы `1 + (1 + q) + (1 + q + q²) = 66051` блоков; вместе с данными получилось бы `16909071` блоков. Эти последние числа также описывают структурное дерево, а не гарантируют его физическую реализуемость.

Двухбайтовая запись при принятом дополнительном соглашении позволяет адресовать только `65535` различных блоков, включая таблицы. Поэтому структурные `16843020` блоков данных физически недостижимы в этой модели.

Точный максимум данных здесь — **65279**. Построение: 12 прямых блоков, 256 блоков через однократную косвенность и 65011 блоков через двукратную. Для этого нужны один однократно-косвенный блок, один корень двукратной косвенности и `ceil(65011 / 256) = 254` его дочерних таблицы: всего 256 служебных блоков. Итого `65279 + 256 = 65535`.

Больше нельзя: для 65280 блоков данных после 12 прямых потребуются хотя бы `ceil((65280 − 12) / 256) = 255` нижних таблиц. Прямо из МАБФ доступна только одна такая таблица, поэтому нужен как минимум ещё один вышестоящий косвенный блок. Получается не меньше `65280 + 255 + 1 = 65536` физических блоков. Наличие трёхкратной косвенности эту нижнюю оценку не уменьшает.

Если ноль или записи кодируются иначе, вывод о физическом пределе требует другого соглашения; исходник однозначно задаёт только структурный расчёт.

# Инвертированная таблица: 32-разрядные адреса и страницы по 4096 байтов

Дан 32-разрядный компьютер со страничной организацией памяти и размером страницы **4096 байтов**. Напишите на Си программу, моделирующую преобразование виртуального адреса в физический с помощью **инвертированной** таблицы страниц. Опишите все необходимые структуры данных.

Виртуальные и физические адреса имеют размер `int`; для адресных вычислений используется 32-разрядный `unsigned`. Объём физической памяти равен объёму виртуального адресного пространства — `2^32` байтов. Все возможные виртуальные страницы рассматриваемого процесса находятся в физической памяти.

Одна запись инвертированной таблицы соответствует одному физическому кадру. Её индекс — номер этого кадра, а поля — PID владельца и номер его виртуальной страницы. Для перевода адреса текущего процесса нужно найти запись, в которой совпадают **и PID, и номер виртуальной страницы**, затем соединить индекс найденной записи со смещением.

Источник: документ «Задачи_вирт_память», условие об инвертированной таблице; фотографии `photo_2026-11-18_21-12-00.jpg` и `photo_2026-11-18_21-12-04.jpg`. Формат ввода/вывода в условии не задан. Восстановленное соглашение для законченной модели: программа сама заполняет корректную таблицу, демонстрирует два преобразования и печатает адреса в шестнадцатеричном виде; функция преобразования работает с PID текущего процесса, полученным через `getpid()`. Отсутствие искомой пары нарушает исходную гарантию и приводит к `exit(EXIT_FAILURE)`, а не к возврату нуля, который сам может быть правильным физическим адресом.

---

# решение

В адресе 12 бит смещения и 20 бит номера виртуальной страницы. Поэтому физических кадров и записей инвертированной таблицы `2^(32-12) = 2^20`. Номер физической страницы отдельно хранить не нужно: это индекс записи.

В отличие от прямой таблицы, индексировать инвертированную таблицу номером виртуальной страницы нельзя. Выполняем линейный поиск пары `(getpid(), Virt_A >> 12)`. Если запись найдена под индексом `i`, физический адрес равен `(i << 12) | (Virt_A & 0xfffU)`.

Полная программа C11/POSIX без интерактивного ввода приведена ниже. Демонстрационный `main` строит полную таблицу текущего процесса с тождественным отображением, затем меняет местами страницы 2 и 7 и печатает два преобразованных адреса; функцию `To_PA_Inverted32` можно вызывать с любой таблицей, удовлетворяющей условию. Для каждой виртуальной страницы текущего процесса должна существовать ровно одна запись. Поскольку число таких страниц равно числу кадров, гарантия размещения всех страниц одного процесса фактически занимает всю моделируемую физическую память; PID всё равно остаётся частью формата записи.

```c
#define _POSIX_C_SOURCE 200809L
#include <limits.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/types.h>
#include <unistd.h>

_Static_assert(UINT_MAX == 0xffffffffU, "unsigned must be 32-bit");
_Static_assert(INT_MAX == 0x7fffffff, "int must be 32-bit");

enum { FRAME_COUNT = 1U << 20 };

typedef struct record {
    pid_t PID;
    unsigned VP;
} record;

unsigned To_PA_Inverted32(unsigned Virt_A, const record *table)
{
    unsigned vp = Virt_A >> 12;
    unsigned offset = Virt_A & 0xfffU;
    pid_t pid = getpid();

    for (unsigned i = 0; i < FRAME_COUNT; ++i) {
        if (table[i].PID == pid && table[i].VP == vp) {
            return (i << 12) | offset;
        }
    }

    /* Нарушена гарантия наличия всех страниц процесса. */
    exit(EXIT_FAILURE);
}

int main(void)
{
    static record table[FRAME_COUNT];
    pid_t pid = getpid();

    for (unsigned i = 0; i < FRAME_COUNT; ++i) {
        table[i].PID = pid;
        table[i].VP = i;
    }
    table[2].VP = 7;
    table[7].VP = 2;

    printf("0x%08X\n", To_PA_Inverted32(0x00002034U, table));
    printf("0x%08X\n", To_PA_Inverted32(0x00000000U, table));
    return 0;
}
```

Программа выводит:

```text
0x00007034
0x00000000
```

Проверка PID обязательна даже при совпадении номера страницы: разные процессы могут иметь одинаковые виртуальные адреса. Скобки вокруг сдвига обязательны, если объединять части адреса сложением; здесь ИЛИ явно объединяет непересекающиеся поля. Время одного преобразования — `O(2^20)` в худшем случае, дополнительная память функции — `O(1)`; сама таблица содержит `2^20` записей.

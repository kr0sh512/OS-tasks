# Ожидание перед вторым fork

Источник: `Test_20251109.md`, задание №4, вариант B.

Допустимая иерархия:

```text
A
├── B
│   └── C
└── D
```

Порядок создания братьев совпадает с порядком в списке. Определите совместимый начальный процесс и все возможные выводы. Необязательно создавать все вершины схемы. `fork` и ожидание существующего ребёнка успешны; `printf` атомарен и небуферизован. Аргументы вычисляются до печати, причём процесс может быть вытеснен между чтением родителя и печатью. R — PID фактического живого усыновителя, не обязательно 1. Заголовки подразумеваются.

```c
int main() {
    if (fork() == 0) {
        printf("%d\n", getpid());
        exit(0);
    }
    wait(NULL);
    if (fork() == 0) {
        printf("%d %d \n", getpid(), getppid());
        exit(0);
    }
    return 0;
}
```

---
# решение

Начальный процесс — только A. Создаются B, затем D; C не создаётся. B обязательно печатает и завершается до создания D. Всего 2 вывода:

```text
B
D A
```
```text
B
D R
```

Первый `wait` в A действительно ждёт единственного ребёнка B. Поэтому обратный порядок строк невозможен. Второго ребёнка A уже не ждёт и может завершиться до чтения `getppid()` в D, что даёт R. Если D прочитал A раньше, последующее завершение A не меняет этот аргумент, даже когда сама печать произошла позднее. В отличие от программ с ожиданием у листьев, здесь `wait` вызывается только в A и имеет ребёнка, так что гарантии успешности не противоречат коду.

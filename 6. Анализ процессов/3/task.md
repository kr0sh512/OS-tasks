# Ожидают все

Источник: `Задачи.md`, «Ожидают все!».

Начальный процесс P2 имеет родителя P1. Первый `fork` создаёт P3; вторые вызовы создают соответственно P4 в P2 и P5 в P3:

```text
P1
└── P2
    ├── P3
    │   └── P5
    └── P4
```

Найдите все возможные выводы. В источнике не гарантировано, что внешний процесс P1 дожидается P2: рассмотрите также его завершение. Фраза источника «все системные вызовы успешны» не может буквально распространяться на завершающий `wait`: нормальное окончание ожидания без детей даёт −1 с `ECHILD`. Считаем, что иных ошибок нет. Считайте каждый вызов `printf` атомарным и небуферизованным: одна строка не перемешивается с другой. Аргументы вычисляются до печати; между чтением PID родителя и самой печатью процесс может быть вытеснен. Все `fork` успешны. PID обозначены символами, а не конкретными числами. `R` — PID фактического усыновителя осиротевшего процесса (не обязательно 1); после усыновления он остаётся жив. Чужие процессы не создают и не завершают детей рассматриваемых процессов. Заголовки стандартных библиотек подразумеваются.

```c
int main(int argc, char **argv) {
    fork();
    printf("%d %d \n", getppid(), getpid());
    if (fork() == 0) {
        printf("%d %d \n", getppid(), getpid());
    }
    while (wait(NULL) != -1);
    return 0;
}
```

---
# решение

Обозначим строки:

```text
a = H P2, где H ∈ {P1, R}
b = P2 P3
c = P2 P4
d = P3 P5
```

Полное множество задаётся шестью порядками:

```text
a b c d
a b d c
a c b d
b a c d
b a d c
b d a c
```

Каждый символ здесь означает целую строку. Для каждого порядка возможны оба значения H: всего 12 символических выводов. Если дополнительно гарантировать жизнь P1 до завершения P2, останутся только H=P1 и 6 выводов; такого ограничения в источнике нет.

Единственные ограничения на печать — a<c и b<d: родитель печатает свою первую строку до второго `fork`. P2 ждёт обоих непосредственных детей, P3 ждёт P5; потому P3, P4 и P5 не сиротеют до своих чтений `getppid`. Первый `printf` исполняют P2 и P3, второй — только новые P4 и P5. `while` отличается от одного `wait`: он собирает всех детей, затем завершается при −1/ECHILD. У листьев этот результат возникает сразу. Буквальное требование успешности вообще каждого `wait` несовместимо с завершающейся программой.

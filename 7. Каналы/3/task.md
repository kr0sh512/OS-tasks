# Два канала: вариант A

Источник: `Test_20251109.md`, задание №6, вариант А.

Что будет выведено на экран? Если возможны несколько вариантов, приведите все. Предполагается, что обращение к функции вывода на экран выполняется атомарно и без буферизации. Все системные вызовы выполняются успешно. Подключение заголовочных файлов опущено. Под успешным чтением одного байта понимается получение этого байта; пустой канал при открытых концах записи блокирует чтение. Процессы, готовые к исполнению, не остаются навсегда без процессорного времени.

```c
int main() {
  char c = '1';
  int fd[2], fd2[2];
  pipe(fd);
  pipe(fd2);

  if(fork() == 0) {
    write(fd[1], &c, 1);
    putchar('2');
    read(fd2[0], &c, 1);
    putchar('3');
    exit(0);
  }

  putchar('4');
  read(fd[0], &c, 1);
  putchar('5');
  write(fd2[1], &c, 1);
  wait(NULL);
  putchar('6');
  return 0;
}
```

---
# решение

Все возможные строки stdout (без завершающего перевода строки):
24536
42536
45236

Родитель печатает 4 раньше 5. Чтобы ребёнок вышел из read(fd2[0],...), родитель должен записать байт во второй канал, а он делает это только после 5. Поэтому 5 раньше 3. Ребёнок печатает 2 раньше 3; wait родителя обеспечивает 3 раньше 6. Итого полный частичный порядок печати: 4<5<3<6 и 2<3, без других отношений между 2,4,5.

Запись ребёнка в первый канал предшествует его 2, но родитель вправе получить записанный байт и напечатать 5 раньше, чем ребёнок получит процессор для печати 2. Поэтому дополнительное ограничение 2<5 было бы ошибкой. Все три положения 2 перед 3 в цепочке 4,5,3,6 осуществимы. Печатаемая в канал цифра 1 на экран не попадает; блокировки разрешаются встречными записями, после чего оба процесса завершаются.

# Процессы и сигналы: общий вариант A, B

Источник: `Test_20251109.md`, задание № 8, **варианты A и B**. В источнике оба варианта заданы одним и тем же листингом; здесь сохранены оба обозначения.

Что будет выведено на стандартный вывод? Перечислите все возможные варианты. Все возвращающиеся системные вызовы считаются успешными; заголовочные файлы опущены. Предполагаются обычные POSIX-процессы, блокирующий канал без посторонних читателей и писателей, отсутствие посторонних сигналов и исправное устройство вывода. Однобайтовые записи на стандартный вывод рассматриваются как неделимые события.

Типографские кавычки исходника заменены на обычные кавычки C; иной код не изменён.

```c
int main(void) {
    pid_t pid;
    int fd[2];
    char x[] = "abc";
    pipe(fd);
    if ((pid = fork()) == 0) {
        write(1, x, 1);
        x[0] = 'f';
        write(fd[1], x, 2);
        x[0] = 's';
    } else {
        read(fd[0], x, 2);
        kill(pid, SIGKILL);
        wait(NULL);
    }
    write(1, x, 1);
    return 0;
}
```

Укажите также, возможна ли последовательность `afs`, и объясните, может ли успешный `read` вернуть только один байт.

---
# решение

Ровно две строки вывода, без перевода строки:

```text
af
asf
```

Первый символ обязательно `a`: ребёнок записывает его до записи в канал. Затем ребёнок одним `write` помещает в канал два байта `fb`. Размер записи не превышает `PIPE_BUF`, запись в блокирующий канал атомарна. Других писателей и читателей нет. Родитель запрашивает ровно два байта: когда данные доступны, доступны оба байта целиком, поэтому в данной программе он получает `fb`, а не одиночный `f`. Сам по себе POSIX допускает короткие чтения, однако здесь нет источника одиночного байта, конкурирующего чтения или обработанного сигнала, который создавал бы такую ситуацию. `SIGKILL` адресован ребёнку, не родителю.

После чтения родитель имеет `x[0] == 'f'`. Ребёнок либо успевает исполнить завершающую запись `s`, либо погибает до неё. В обоих случаях родитель сначала выполняет `wait(NULL)` и лишь затем печатает `f`. Следовательно, если `s` существует, он обязательно стоит перед родительским `f`.

`afs` невозможно: оно требовало бы печати ребёнка после успешного ожидания его завершения. Не следует считать `kill` ожиданием смерти: нужный порядок здесь обеспечивает именно `wait`.

Если ребёнок уже завершился, но ещё не собран, он остаётся доступным для `wait`; у родителя действительно имеется ребёнок. Случай `ECHILD`, характерный для вызова `wait` в процессе без детей, здесь не возникает при указанных предпосылках. Успешный `kill` не обязательно означает, что ребёнок ещё не успел напечатать `s`.

# Связное размещение: число обменов, вариант 2

Файл хранится в файловой системе со связным размещением блоков. Требуется прочитать байты из диапазона `D = (3073, 8200]`. Размер блока `N = 2060` байт, размер ссылки на следующий блок файла `M = 10` байт. Нумерация байтов файла начинается с `K = 0`. Определите минимальное число обменов для получения запрошенных данных.

Соглашения модели: один обмен читает один блок ФС целиком; ссылка занимает `M` байт внутри блока, поэтому полезные данные занимают `N − M` байт. Номер первого блока файла уже известен, но его содержимое и все последующие блоки отсутствуют в кэше. Индекса для произвольного перехода нет: номер следующего блока узнаётся только из прочитанного предыдущего. Расходы на поиск самого файла не учитываются. Файл достаточно длинный, все чтения успешны, а границы диапазонов относятся к целым номерам байтов файла. При нескольких диапазонах разрешён один общий проход с сохранением уже прочитанного.

Источник: «Задачи.md», «Быстросчет обменов», вариант 2.

---

# решение

Полезная ёмкость блока `P = N − M = 2060 − 10 = 2050` байт. Блок с индексом `j`, считая с нуля, содержит номера байтов от `K + jP` до `K + (j + 1)P − 1`.

Левая граница исключена, правая включена: нужны целые номера от 3074 до 8200 включительно. Поскольку K = 0, номер 8200 уже является его смещением от начала файла.

Индекс последнего нужного блока:

`j_last = floor((b_last − K) / P) = floor((8200 − 0) / 2050) = 4`.

Чтобы получить ссылку на этот блок, требуется последовательно прочитать все блоки от нулевого до него включительно. Поэтому

`E = j_last + 1 = 5` обменов.

Первый нужный байт находится в блоке с индексом `floor((3074 − 0) / 2050) = 1`, но вычитать этот индекс из числа обменов нельзя: предыдущие блоки всё равно читаются ради ссылок. Один последовательный проход достигает указанной нижней границы, значит ответ минимален.

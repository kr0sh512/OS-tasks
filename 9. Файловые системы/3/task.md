# МАБФ: структурная ёмкость, вариант 3

В файловой системе размер блока `N = 4096` байт, размер записи с номером блока `s = 8` байт, длина массива адресов блоков файла (МАБФ) `L = 13` записей. Найдите максимальное число блоков **данных** одного файла, допускаемое структурой адресации.

Восстановленное соглашение: используется классическая Unix-схема — `L − 3` прямых адресов и по одному адресу блока однократной, двукратной и трёхкратной косвенности. Каждый косвенный блок содержит `q = N / s` записей. Сам МАБФ находится вне учитываемых блоков данных; косвенные блоки содержат адреса, а не данные файла.

Отдельно обсудите, достижим ли структурный предел при конечном диапазоне номеров блоков. В исходнике не задано кодирование номеров и не сказано, зарезервирован ли ноль. Для численного сравнения дополнительно рассмотрите обычное соглашение: запись — беззнаковое целое из `8s` бит, `0` означает отсутствие блока, номера всех блоков данных и косвенности лежат в одном диапазоне `1..2^(8s) − 1`. Доступных физических блоков должно быть достаточно; фактический размер ФС не задан.

Источник: «Задачи.md», «Быстросчет блоков», вариант 3.

---

# решение

В одном косвенном блоке `q = 4096 / 8 = 512` записей; прямых адресов `d = 13 − 3 = 10`.

Структурная ёмкость данных:

`D = d + q + q² + q³ = 10 + 512 + 262144 + 134217728 = 134480394` блоков.

Это число блоков данных, а не сумма данных и таблиц. При полном заполнении структуры таблицы занимали бы `1 + (1 + q) + (1 + q + q²) = 263171` блоков; вместе с данными получилось бы `134743565` блоков. Эти последние числа также описывают структурное дерево, а не гарантируют его физическую реализуемость.

При дополнительном соглашении о номерах `1..18446744073709551615` всего дерева достаточно мало: `134743565 ≤ 18446744073709551615`. Поэтому при наличии нужного числа физических блоков структурный предел `134480394` блоков данных достижим. Без размера самой ФС нельзя утверждать, что конкретный файл действительно сможет занять столько блоков.

# Очередь из пяти сообщений: два получателя

Источник: `Test_20251109.md`, задание № 7, вариант C.

Перечислите все возможные варианты вывода программы. Вывод атомарен и не буферизуется. По исходному условию все системные вызовы успешны, заголовочные файлы опущены, `msgId` — идентификатор существующей пустой очереди, а размер очереди — **пять сообщений**.

```c
int main() {
    struct { long type; char data[1]; } msg;
    msgId = msgget(IPC_PRIVATE, 0);

    if (fork()) {
        msg.type = 2; msg.data[0] = '1'; msgsnd(msgId, &msg, 1, 0);
        msg.type = 2; msg.data[0] = '2'; msgsnd(msgId, &msg, 1, 0);
        msg.type = 1; msg.data[0] = 'a'; msgsnd(msgId, &msg, 1, IPC_NOWAIT);
        msg.type = 3; msg.data[0] = 'b'; msgsnd(msgId, &msg, 1, 0);
        msg.type = 3; msg.data[0] = '5'; msgsnd(msgId, &msg, 1, 0);
        msg.type = 1; msg.data[0] = '7'; msgsnd(msgId, &msg, 1, IPC_NOWAIT);
        msg.type = 3; msg.data[0] = 'd'; msgsnd(msgId, &msg, 1, 0);
        msg.type = 1; msg.data[0] = 'f'; msgsnd(msgId, &msg, 1, IPC_NOWAIT);
        msg.type = 1; msg.data[0] = 'U'; msgsnd(msgId, &msg, 1, 0);
    }

    msgrcv(msgId, &msg, 1, -2, 0); putchar(msg.data[0]);
    msgrcv(msgId, &msg, 1, 1, IPC_NOWAIT); putchar(msg.data[0]);
    msgrcv(msgId, &msg, 1, 1, MSG_EXCEPT); putchar(msg.data[0]);

    return 0;
}
```

Не исправляйте несогласованные предпосылки без оговорки. В показанном коде отсутствует объявление `msgId`: для операционного анализа явно предоставляется внешнее `int msgId;`, иначе листинг не компилируется как самостоятельная программа. Используется Linux System V IPC с `MSG_EXCEPT`. Не путайте успешность уже вернувшихся вызовов с гарантией завершения блокирующего вызова. Посторонних участников очереди нет.

# решение

## Проблемы буквальной постановки

`msgget(IPC_PRIVATE, 0)` не использует названную в преамбуле существующую очередь: он создаёт новую очередь с правами `000`, перезаписывая её идентификатор. Для обычного процесса без `CAP_IPC_OWNER` отправки и получения завершаются `EACCES`, даже если он владелец. Поэтому для обычного процесса буквальное обещание успеха нарушается. Linux-возможность `CAP_IPC_OWNER` в управляющем пространстве имён может обойти эту проверку; без уточнения полномочий нельзя категорически утверждать ни доступность, ни абсолютную недоступность очереди.

Сам `msgget` не устанавливает ёмкость в пять сообщений: реальный Linux ограничивает очередь параметром `msg_qbytes` в байтах и дополнительными ограничениями числа сообщений. Указанная ёмкость принимается ниже как отдельная учебная предпосылка о ресурсе, а не как следствие написанного `msgget`.

Наконец, даже после предоставления прав **полностью завершившегося исполнения со всеми успешными вызовами нет**: прежде чем родитель начнёт получать, он должен отправить девять сообщений. До этого сообщения может получать только ребёнок, выполняющий всего три получения. Значит, в очереди потребовалось бы разместить не менее `9 - 3 = 6` сообщений при ёмкости 5. Это невозможно.

Если понимать успех как обязательный успешный возврат каждого вызова, множество допустимых исполнений пусто. Если понимать его как отсутствие ошибок у вернувшихся вызовов, разрешены зависшие исполнения; они полностью разобраны далее. Нельзя подменить их шестисимвольными строками якобы завершившейся программы.

## Явно отделённая операционная модель

Для анализа порядка операций предоставим объявление `msgId`, доступ на чтение/запись (например, **явно изменим** режим создания с `0` на `0600` либо предоставим право обхода) и ёмкость ровно пять однобайтовых сообщений. Очередь изначально пуста, других участников нет, `fork` успешен. Всякая вернувшаяся операция IPC должна быть успешной. `IPC_NOWAIT` сам по себе успеха не гарантирует: отправка в полную очередь дала бы `EAGAIN`, получение без подходящего сообщения — `ENOMSG`; такие расписания исключены условием, а не замалчиваются как невозможные вообще.

### Точная конечная машина

Ниже машина охватывает все девять отправок и все **шесть написанных в коде** получений, не утверждая достижимости последних трёх. Получение и последующий `putchar` — разные шаги: их нельзя склеивать, поскольку печати разных процессов вообще могли бы переставляться.

Состояние состоит из:

- упорядоченной очереди `Q`, `0 <= |Q| <= 5`;
- позиции родителя в списке операций;
- позиции ребёнка в списке операций;
- по одному локальному регистру принятого символа для каждого процесса;
- уже напечатанной строки `w`.

Начальное состояние: `Q = []`, обе позиции в начале, `w` пусто. Родительский список:

```text
S(2,'1',0), S(2,'2',0), S(1,'a',NOWAIT),
S(3,'b',0), S(3,'5',0), S(1,'7',NOWAIT),
S(3,'d',0), S(1,'f',NOWAIT), S(1,'U',0),
R(-2,0), O, R(1,NOWAIT), O, R(1,EXCEPT), O, END
```

Список ребёнка:

```text
R(-2,0), O, R(1,NOWAIT), O, R(1,EXCEPT), O, END
```

За один переход выбирается один процесс и исполняется только его очередная операция:

1. `S(t,c,...)` при `|Q| < 5` дописывает `(t,c)` в конец `Q` и сдвигает позицию. При `|Q| == 5` блокирующая отправка ждёт без изменения состояния; `NOWAIT` даёт переход в состояние ошибки `EAGAIN`.
2. `R(-2,0)` выбирает минимальный имеющийся тип из множества `{1,2}`, затем самое старое сообщение этого типа. Если таких сообщений нет, операция блокируется.
3. `R(1,NOWAIT)` выбирает самое старое сообщение точно типа 1; при его отсутствии происходит переход в ошибку `ENOMSG`.
4. `R(1,EXCEPT)` выбирает самое старое сообщение **не** типа 1; при отсутствии такого сообщения блокируется. `MSG_EXCEPT` меняет правило именно при положительном `msgtyp`, а не при нулевом или отрицательном.
5. Успешное `R` удаляет только выбранное сообщение, сохраняет его символ в локальном регистре **своего** процесса и сдвигает его позицию. Оно пока ничего не печатает.
6. `O` дописывает сохранённый локальный символ в `w` и сдвигает позицию. `END` завершает процесс и не печатает.

Полный алгоритм перебора: из начального состояния разветвлять каждый разрешённый переход обоих процессов до завершения или блокировки; состояния ошибок отбрасывать вместе со всеми их продолжениями. Вызов `NOWAIT`, для которого доступен только ошибочный переход, нельзя объявлять «блокирующим»: максимальный запуск с таким следующим реально исполняемым вызовом нарушает предпосылку успеха. Бесконечное откладывание доступного шага исключается справедливостью. Номер каждой операции только увеличивается: успешных переходов не больше `9 + 6 + 6 = 21`, поэтому это конечный точный перебор, не эвристика.

### Сведение машины к полному ответу

Родитель не может перейти к первому `R`: к завершению девятой отправки ребёнок удалил бы не более трёх сообщений и очередь содержала бы не менее шести. Поэтому **все три родительских получения недостижимы**. Отдельные шаги `R` и `O` не дают дополнительных перестановок вывода в данном случае: печатает только ребёнок.

В любом справедливом максимальном исполнении без ошибочных возвратов ребёнок успевает выполнить три получения и три печати, родитель успешно отправляет первые восемь сообщений и навсегда блокируется на девятой, отправляющей `'U'`. Возможны ровно два окончательных вывода, каждый без перевода строки:

```text
1a2
a71
```

Доказательство выбора символов:

- Если первое получение ребёнка произошло до появления `'a'`, оно берёт `(2,'1')`: среди имеющихся подходящих сообщений это самое старое минимального типа. Второе получение обязано взять `(1,'a')`: если `'a'` ещё нет, `NOWAIT` вернул бы ошибку и расписание не удовлетворяло бы предпосылке. Третье получение с `EXCEPT` берёт старейшее сообщение не типа 1 — `(2,'2')`. Получается `1a2`.
- Если `'a'` уже есть перед первым получением, минимальный тип равен 1 и выбирается `(1,'a')`. Следующее сообщение типа 1, которое ребёнок может успешно получить, — `(1,'7')`. Перескочить к `'f'` невозможно: до второго получения отправки 1–6 с одним удалением заполняют очередь; седьмая отправка блокируется, так что восьмая с `'f'` ещё не выполняется. После получения `'7'` третье получение выбирает старейшее сообщение не типа 1 — `(2,'1')`. Получается `a71`.

Оба порядка достижимы. Для `1a2` можно выполнить отправки 1–2, первое получение/печать, отправку 3, второе получение/печать, третье получение/печать, затем оставшиеся отправки до блокировки на девятой. Для `a71` можно выполнить отправки 1–3, первое получение/печать, отправки 4–6, второе получение/печать, третье получение/печать, отправки 7–8 и блокировку на девятой. Во всех этих шагах `NOWAIT` успешен.

Во втором случае в момент зависания очередь равна `(2,'2'), (3,'b'), (3,'5'), (3,'d'), (1,'f')`; в первом — `(3,'b'), (3,'5'), (1,'7'), (3,'d'), (1,'f')`. У ребёнка больше нет операций, способных освободить место.

Пустая строка и собственные префиксы `1`, `1a`, `a`, `a7` встречаются как **промежуточные наблюдения** и как результат бесконечного несправедливого откладывания доступных шагов. Они не являются дополнительными окончательными выводами справедливых максимальных исполнений. Завершившихся допустимых исполнений по-прежнему нет.

# Незаметные вычисления

Процесс создаёт две нити, условно обозначенные `A` и `B`. Проанализируйте следующий фрагмент C. Подключение `<pthread.h>` и `<stdio.h>` в записи опущено.

```c
int counter = 0;

void func(void* arg) {
    int a = *(int*) arg;
    counter += a;
    printf("%ld:%d\n", pthread_self(), counter());
    pthread_exit(NULL);
}

int main(void) {
    pthread_t t1, t2;
    int a = 2, b = 3;
    pthread_create(&t1, NULL, func, &a); /* A */
    pthread_create(&t2, NULL, func, &b); /* B */
    pthread_join(t1, NULL);
    pthread_join(t2, NULL);
    return 0;
}
```

В исходнике заявлены успешность системных вызовов, атомарность операций и отсутствие буферизации. Требуется перечислить все возможные выводы. Сначала установите, является ли записанный фрагмент корректной программой C и достаточно ли этих гарантий для ответа о реальной программе.

Отдельно рассмотрите предполагаемую учебную интерпретацию: `counter()` — опечатка вместо `counter`, сигнатура функции нити исправлена на `void *func(void *)`, идентификатор выводится символом `A` или `B`. В этой **абстрактной модели**, а не в исходной программе C, весь оператор `counter += a` и весь оператор вывода с чтением счётчика считаются отдельными атомарными действиями; память последовательна. Запишите все возможные выводы для этой модели. Целое число после двоеточия — значение общего счётчика в момент атомарного вывода.

Источник: «Задачи.md», раздел «Задачи на нити», «Незаметные вычисления». Учебная модель сформулирована явно, поскольку слово «атомарность» само по себе не задаёт ни способ синхронизации C, ни границы составного действия.

---

# решение

## Исходная программа C

`counter` объявлен как объект типа `int`, поэтому `counter()` — недопустимая попытка вызвать целое число как функцию. Требуется диагностика транслятора; у записанного фрагмента нет определённого вывода исполнимой программы.

Кроме того, `pthread_create` требует адрес функции типа `void *(*)(void *)`, а передан `void (*)(void *)`. Это несовместимые типы. Для `pthread_t` POSIX не гарантирует тип `long`: `%ld` не является переносимым способом печати идентификатора нити.

Даже после исправления этих механических ошибок обычный `int counter` одновременно читается и изменяется без синхронизации. В реальной программе C это гонка данных и неопределённое поведение. Атомарность вывода не делает `counter += a` атомарным и не устраняет гонку. Для работающего решения нужны, например, мьютекс вокруг всех доступов или атомарный счётчик с точно оговорёнными операциями; это уже изменение программы, а не свойство исходного фрагмента.

## Явно заданная учебная модель

Обозначим прибавления `U_A`, `U_B`, а выводы `P_A`, `P_B`. Необходимы только зависимости `U_A < P_A` и `U_B < P_B`. Оба прибавления в любом случае дают итог `5`.

Если `A` выводит до прибавления `B`, получается `A:2`, затем `B:5`. Симметрично возможен `B:3`, затем `A:5`. Если оба прибавления уже выполнены до первого вывода, обе нити печатают `5`, в любом порядке.

Итак, **ровно четыре** вывода модели; пустая строка ниже разделяет варианты и не является частью вывода:

```text
A:2
B:5

A:5
B:5

B:3
A:5

B:5
A:5
```

Итог относится только к указанной модели атомарных операторов. Если чтение аргумента `printf` и фактический вывод считать разными действиями, множество изменится: захваченное ранее значение может быть напечатано позже другого вывода.

# На отдохнуть

Источник: `Задачи.md`, «Задачка на отдохнуть (ли)».

Начальный процесс A создаёт B, затем C:

```text
A
├── B
└── C
```

Найдите все возможные выводы. В источнике сказано: `printf` атомарен, но «с буферизацией не на стороне процесса». Эта фраза сама по себе не определяет порядок доставки и момент наблюдения. Для определённого ответа используйте явную операционную модель: каждый `printf` атомарно добавляет одну готовую строку в общую внешнюю FIFO-очередь; очередь не копируется `fork`, сохраняется после завершения отправителя, не теряет строки и в итоге полностью опустошается. Требуется окончательный поток, а не промежуточное содержимое очереди. Системные вызовы успешны. Аргументы `printf` вычисляются до добавления строки, и процесс может быть вытеснен между вычислением и добавлением. R — PID живого усыновителя, не обязательно 1. Заголовки подразумеваются.

```c
int main(int argc, char **argv) {
    if (fork() == 0) {
        printf("%d %d \n", getppid(), getpid());
        exit(0);
    }
    if (fork() == 0) {
        printf("%d %d \n", getppid(), getpid());
        exit(0);
    } else {
        printf("%d \n", getpid());
    }
    return 0;
}
```

---
# решение

В заданной FIFO-модели всего 14 выводов. Ниже каждая строка таблицы задаёт порядок трёх полных строк вывода. Обозначения: a — строка `A`, b — строка `H_B B`, c — строка `H_C C`.

```text
Порядок   H_B       H_C       Число
b c a     A         A         1
c b a     A         A         1
b a c     A         A или R   2
c a b     A или R   A         2
a b c     A или R   A или R   4
a c b     A или R   A или R   4
```

Все выборы в одной строке таблицы независимы. Например, при a b c допустимы и `R B`, затем `A C`: C мог прочитать A заранее, быть вытеснен, а допечатать после усыновления B. Нельзя считать `getppid()` выполняющимся в момент появления строки у наблюдателя.

До добавления a процесс A не может завершиться. Поэтому ребёнок, чья строка добавлена раньше a, обязательно прочитал A. После a значение его аргумента может быть A или R. Внешняя FIFO-буферизация лишь откладывает доставку, не размножает строки: здесь нет копирования пользовательского буфера при `fork`.

Без явно принятой FIFO-модели исходная формулировка недоопределена: неизвестно, сохраняет ли внешний буфер порядок, когда выдаёт строки и может ли потерять их. Число 14 относится именно к изложенному соглашению, а не к любому мыслимому устройству буферизации.

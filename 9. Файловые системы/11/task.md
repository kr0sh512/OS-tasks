# Связное размещение: число обменов, вариант 3

Файл хранится в файловой системе со связным размещением блоков. Требуется прочитать байты из диапазона `D = [8675, 9876)`. Размер блока `N = 512` байт, размер ссылки на следующий блок файла `M = 8` байт. Нумерация байтов файла начинается с `K = 1`. Определите минимальное число обменов для получения запрошенных данных.

Соглашения модели: один обмен читает один блок ФС целиком; ссылка занимает `M` байт внутри блока, поэтому полезные данные занимают `N − M` байт. Номер первого блока файла уже известен, но его содержимое и все последующие блоки отсутствуют в кэше. Индекса для произвольного перехода нет: номер следующего блока узнаётся только из прочитанного предыдущего. Расходы на поиск самого файла не учитываются. Файл достаточно длинный, все чтения успешны, а границы диапазонов относятся к целым номерам байтов файла. При нескольких диапазонах разрешён один общий проход с сохранением уже прочитанного.

Источник: «Задачи.md», «Быстросчет обменов», вариант 3.

---

# решение

Полезная ёмкость блока `P = N − M = 512 − 8 = 504` байт. Блок с индексом `j`, считая с нуля, содержит номера байтов от `K + jP` до `K + (j + 1)P − 1`.

Правая граница исключена: нужны целые номера от 8675 до 9875 включительно. При K = 1 смещение последнего нужного байта равно 9875 − 1 = 9874.

Индекс последнего нужного блока:

`j_last = floor((b_last − K) / P) = floor((9875 − 1) / 504) = 19`.

Чтобы получить ссылку на этот блок, требуется последовательно прочитать все блоки от нулевого до него включительно. Поэтому

`E = j_last + 1 = 20` обменов.

Первый нужный байт находится в блоке с индексом `floor((8675 − 1) / 504) = 17`, но вычитать этот индекс из числа обменов нельзя: предыдущие блоки всё равно читаются ради ссылок. Один последовательный проход достигает указанной нижней границы, значит ответ минимален.

# Найди меня: посложнее

Источник: `Задачи.md`, «Найди меня», вариант «Посложнее».

Дана допустимая иерархия PID:

```text
A
└── B
    ├── C
    │   └── E
    └── D
```

Программа запускается из неуказанного процесса. Не все нарисованные процессы обязательно создаются: но каждый созданный ребёнок должен соответствовать ребру этой иерархии. Порядок создания C и D в этом источнике отдельно не задан. Определите все совместимые начальные процессы, все способы назначения PID создаваемым процессам и все возможные выводы.

Рассматривается полный запуск `main`, без чужих детей и без ранее выполненной части этой программы; необязательные вершины не добавляют невидимые вызовы `wait`. Если рассматриваются несколько независимых полных запусков, один PID не может одновременно принадлежать двум экземплярам. Внешний родитель начального процесса не обязан ждать. Для начального A его неуказанный родитель обозначается Q. Это дополнительное обозначение необходимо, поскольку исходная схема не задаёт PID родителя A. Стандартное завершение `wait` с −1/ECHILD при отсутствии детей не считается запрещённой ошибкой: буквальная гарантия успешности всех `wait` противоречила бы коду. Иных ошибок нет.

Считайте каждый вызов `printf` атомарным и небуферизованным: одна строка не перемешивается с другой. Аргументы вычисляются до печати; между чтением PID родителя и самой печатью процесс может быть вытеснен. Все `fork` успешны. PID обозначены символами, а не конкретными числами. `R` — PID фактического усыновителя осиротевшего процесса (не обязательно 1); после усыновления он остаётся жив. Чужие процессы не создают и не завершают детей рассматриваемых процессов. Заголовки стандартных библиотек подразумеваются.

```c
int main(void) {
    if (!fork()) {
        printf("%d %d\n", getpid(), getppid());
    }
    fork();
    wait(NULL);
    printf("%d %d\n", getpid(), getppid());
}
```

---
# решение

Единственный совместимый старт — B. Первый `fork` создаёт C, затем B создаёт D, а C создаёт E. Два ребёнка и внук одного из них требуются самим кодом; только B имеет такую форму поддерева. Ни A, ни C, ни D, ни E не подходят. Два непересекающихся полных экземпляра разместить в этой схеме нельзя.

Полное множество из 38 символических выводов задаётся следующей конечной системой. Обозначим пять строк:

```text
a = C H_a
b = B H_b
c = C H_c
d = D H_d
e = E C
```

Выберите перестановку пяти строк, удовлетворяющую:

```text
a < e < c
(c < b) ИЛИ (d < b)
```

Здесь `<` — порядок появления целых строк. Затем выберите поля:

```text
H_b ∈ {A,R};
H_a,H_c,H_d ∈ {B,R};
H_a=R разрешено только при b<a;
H_c=R разрешено только при b<c;
H_d=R разрешено только при b<d;
H_a=R влечёт H_c=R.
```

Других ограничений нет. Каждый такой выбор даёт ровно один допустимый вывод, и всякий вывод описывается этими правилами. Если внешний A гарантированно остаётся жив, берётся только H_b=A и получается 19 выводов; в исходнике этой гарантии нет.

Подсчёт 19 для фиксированного H_b:

```text
Порядок       Число вариантов остальных полей
a e c d b     1
a e d c b     1
a d e c b     1
d a e c b     1
a e c b d     2
d b a e c     3
d a b e c     2
a d b e c     2
d a e b c     2
a d e b c     2
a e d b c     2
Итого         19
```

В строке d b a e c пара (H_a,H_c) принимает (B,B), (B,R) или (R,R). В строках, где a<b<c, H_a=B, H_c=B или R. В a e c b d только H_d меняется. Выбор H_b удваивает сумму.

Доказательство: C сначала печатает a, создаёт E, ждёт его завершения и печатает c. Поэтому e между a и c, а E всегда видит родителя C. B вызывает только один `wait`: он может дождаться D или C, но не обязан обоих. Строка b появляется после строки хотя бы одного завершившегося ребёнка, то есть после d либо c. После b процесс B может сразу завершиться или задержаться; C и D могут стать сиротами. Два чтения родителя в C идут в программном порядке, поэтому переход R→B невозможен, а B→R возможен. Чтение B может предшествовать печати на произвольное время, поэтому строка с родителем B допустима и после b.

Достаточность: выбранные старые значения родителя можно прочитать до завершения B и отложить печать; завершение B размещается после b, перед первым чтением R. Условия на поля и порядок гарантируют существование такой границы. Если d после b, то c до b, и B ждёт C; иначе при необходимости он ждёт D. Все листовые `wait` дают −1/ECHILD. Если запретить этот результат буквально, ни одного полного успешного исполнения не существует.

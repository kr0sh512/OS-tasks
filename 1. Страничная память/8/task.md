# Инвертированная таблица: 16-разрядные адреса и страницы по 512 байтов

В компьютере используется страничная организация памяти с **16-разрядными** виртуальными и физическими **байтовыми** адресами. Размер страницы — **512 байтов**. Тип `unsigned short` занимает 16 бит. Реализуйте на Си функцию преобразования адреса текущего процесса через инвертированную таблицу страниц:

```c
unsigned short To_PA_Inverted16(const record *table, unsigned short VA);
```

Здесь `record` содержит `pid_t PID` — идентификатор владельца физического кадра и `unsigned short VP` — номер его виртуальной страницы. Индекс записи в таблице является номером физического кадра. PID текущего процесса нужно получить с помощью `getpid()`. Совпадения одного номера страницы без совпадения PID недостаточно.

Источник: фотография доски `photo_2026-11-18_21-12-16.jpg`. Полный текст условия на снимке отсутствует. Для однозначной законченной задачи восстановлены соглашения: физическая память занимает всё 16-разрядное адресное пространство (`2^16` байтов), таблица содержит 128 записей, вызывающая сторона передаёт корректный массив такого размера, а нужная пара `(PID, VP)` существует и единственна. В отличие от задачи с 32-разрядными адресами здесь не требуется, чтобы все возможные страницы текущего процесса находились в памяти одновременно. Если искомой пары нет, модель завершает процесс с кодом `EXIT_FAILURE`; это защита от нарушения восстановленного предусловия, а не возвращаемый физический адрес.

Нужно описать структуру таблицы и разбиение адреса, затем привести корректную реализацию. Отдельный ввод с клавиатуры или обработка командной строки не требуются.

---

# решение

`512 = 2^9`, поэтому младшие 9 бит адреса содержат смещение, а старшие `16 - 9 = 7` — номер виртуальной страницы. Число кадров равно `2^7 = 128`. Инвертированная таблица хранит для каждого кадра пару `(PID, VP)`; номер самого кадра уже задан индексом.

После поиска индекса `i` получаем адрес `(i << 9) | offset`. Преждевременно вычислять адрес после окончания цикла нельзя: если поиск неуспешен, индекс равен 128 и уже не является номером кадра. В наброске выражение вида `offset + i << 9` также неверно: оно сдвигает сумму вместе со смещением. В решении сдвиг заключён в скобки, а непересекающиеся поля объединены ИЛИ.

Код — единица трансляции C11/POSIX. Вычисления выполняются в `unsigned`, вмещающем все 16-разрядные адреса. Явное приведение результата к `unsigned short` безопасно, поскольку `i < 128` и `offset < 512`. Тип `pid_t` предоставляет системный заголовок `<sys/types.h>`.

```c
#define _POSIX_C_SOURCE 200809L
#include <limits.h>
#include <stdlib.h>
#include <sys/types.h>
#include <unistd.h>

_Static_assert(USHRT_MAX == 0xffffU, "unsigned short must be 16-bit");

enum { FRAME_COUNT = 128 };

typedef struct record {
    pid_t PID;
    unsigned short VP;
} record;

unsigned short To_PA_Inverted16(const record *table, unsigned short VA)
{
    unsigned vp = (unsigned)VA >> 9;
    unsigned offset = (unsigned)VA & 0x1ffU;
    pid_t pid = getpid();

    for (unsigned i = 0; i < FRAME_COUNT; ++i) {
        if (table[i].PID == pid && (unsigned)table[i].VP == vp) {
            return (unsigned short)((i << 9) | offset);
        }
    }

    exit(EXIT_FAILURE);
}
```

Время преобразования — `O(128)` в худшем случае, дополнительная память функции — `O(1)`. Поля `VP` имеют смысл только для занятых кадров; значение PID 0 можно использовать как признак свободного кадра, поскольку `getpid()` возвращает положительный PID.
